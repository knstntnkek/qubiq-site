# VPN-туннель и платформы

*Настройки → Расширенные → VPN-туннель и Xray* содержит платформенные параметры
туннеля и диагностику Xray. Это продвинутые настройки; большинству
пользователей не нужно их менять.

## Общее поведение <!-- #common-behavior -->

- **Адреса** — IPv4/IPv6-адреса туннеля показаны только для чтения.
- **DNS** — редактируйте IPv4/IPv6-резолверы; IPv6 включается отдельно.
- **Исходящий интерфейс** — на Windows и Linux выберите сетевой интерфейс,
  через который есть выход в интернет. Если сохранённый интерфейс больше
  недействителен, Qubiq спросит снова.

## Apple (iOS / macOS) <!-- #apple-ios-macos -->

Платформы Apple предлагают постоянное подключение (always-on) и поведение в зависимости от сети, а
также варианты исключений при полном захвате трафика. iOS также может
скрывать индикатор VPN в конфигурациях, где система это позволяет.

## Android <!-- #android -->

Выберите, используют ли VPN все приложения, только выбранные или все кроме
выбранных. Выбор приложений поддерживает поиск и держит отмеченные элементы
рядом. Доступ других приложений к автоматизации настраивается на отдельной
странице.

## Windows <!-- #windows -->

Пакеты MSIX и переносимые/установочные сборки показывают разные системные
параметры VPN. Все сборки Windows используют общие настройки DNS и
исходящего интерфейса. При первом подключении может появиться однократный
системный запрос безопасности; разрешите его, чтобы ядро VPN запустилось.

## Linux <!-- #linux -->

Linux использует общие настройки DNS и исходящего интерфейса. На Linux нет страницы
платформенных параметров и резервной копии.

## Вкладка Xray <!-- #xray-tab -->

Вкладка **Xray** предназначена для диагностики и продвинутых ресурсов:

- **Состояние запуска** — имя и версия ядра.
- **Проверка и диагностика** — текущее состояние, ошибки, конфигурация и
  журналы для устранения неполадок.
- **Подключение и ресурсы** — обновления данных маршрутизации, проверка
  задержки и параметры подключения к серверам.
- **Общий доступ и интерфейсы** — локальный прокси для доверенных сетей и
  локальный HTTP API, где он доступен.

Не включайте общий доступ LAN в недоверенных сетях: локальный прокси не
использует аутентификацию.
