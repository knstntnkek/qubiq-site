# Резервная копия и восстановление

Пункт резервной копии живёт в **«Настройки → раздел Данные»**. Одно
привязанное хранилище служит и для копии, и для восстановления — ни
списка версий, ни двусторонней синхронизации, ни облачного аккаунта для
входа.

> **Файл резервной копии незашифрован.** Он содержит учётные данные
> узлов, URL подписок и закрытые ключи Age — Base64 это кодировка,
> а не секретность. Выбирайте его расположение соответственно.

## Хранилища по платформам <!-- #targets-by-platform -->

| Платформа | Хранилище |
| --- | --- |
| iOS / macOS | iCloud Drive (`Documents/Qubiq-backup.json`) или выбранный файл — с общими копией, восстановлением и расписанием |
| Android | Документ в системном диалоге (SAF) — показывает настоящее имя файла провайдера |
| Windows | Файл в выбранной, синхронизируемой OneDrive папке |
| Linux | Недоступно |

Выбирайте хранилище вне служебных папок приложения, чтобы файл пережил
удаление — переустановка теряет привязку, а не файл; для восстановления
достаточно выбрать тот же файл снова.

## Как работает привязка <!-- #how-binding-works -->

Привязка сначала проверяет содержимое файла:

- **Пустой файл** → первая копия пишется напрямую.
- **Файл с содержимым** → выбор *восстановить* или *перезаписать*;
  отмена оставляет старую привязку и файл нетронутыми.

Следующие копии перезаписывают тот же файл. Отвязка и смена хранилища
всегда доступны; отвязка никогда не удаляет файл, как и очистка данных
приложения.

## Автоматическая копия <!-- #automatic-backup -->

Переключатель рядом с заголовком раздела плюс настройка интервала —
запланированные записи идут в привязанное хранилище по тем же правилам,
что и ручные (включая условия простоя VPN). Успешная запись значит, что
файл принят локально — завершение облачной синхронизации на совести
провайдера.

## Восстановление <!-- #restore -->

Восстановление читает весь файл, проверяет его и показывает предпросмотр
с подтверждением до любой замены. Оно меняет ресурсы подключения — узлы,
подписки, конфигурации, маршруты — и настройки VPN той же платформы,
сохраняя локальные привязки, разрешения и предпочтения. После
восстановления данные тарифа обновляются при следующем обычном
обновлении.

Если запись привязки не удалась, восстановление не начинается; если
неудачно восстановление, исходная привязка откатывается.

## Очистка и удаление данных <!-- #cleanup-vs-wipe -->

Две разные необратимые операции в «Настройках»:

- **Удалить ресурсы подключения** — убирает узлы, подписки, Raw и кэши,
  группы вручную, пользовательские маршруты и Geodata, а также старые
  журналы запусков. Сохраняет правила платформы, предпочтения, объект
  входа, привязку резервной копии, разрешения API/автоматизации и
  стандартные Geodata.
- **Удалить все данные приложения** — дополнительно отменяет объект входа, очищает
  предпочтения и пересобирает значения по умолчанию. Только это удаляет
  локальную привязку резервной копии.

Ни одна не удаляет внешние файлы — копии в iCloud, OneDrive или SAF
остаются на месте.
