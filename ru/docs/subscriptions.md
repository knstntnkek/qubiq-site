# Подписки и провайдеры

Подписка — это список серверов, который ведёт ваш провайдер: Qubiq
скачивает его по HTTPS, импортирует записи и обновляет по требованию или
по расписанию. Форма добавления спрашивает ровно две вещи: **название**
(необязательно) и **HTTPS-URL**.

## Режимы: управляемый приложением и управляемый провайдером {#modes-app-managed-vs-provider-managed}

Содержимое ответа решает, как ведут себя его записи:

- **Обычные узлы** — записи в стиле ссылок под вашим управлением.
- **Полные конфигурации** — целые документы Xray JSON под управлением
  провайдера (например, панели Remnawave): каждая запускает собственную
  маршрутизацию и доступна только для чтения.

Новый источник появляется с типом панели Remnawave по умолчанию и
неопределённым режимом — формат ответа решает всё: обычные узлы делают
его управляемым приложением, полный JSON — управляемым провайдером, и
сохранённый режим отображается на источнике после этого.

Источник Remnawave, ответивший не-JSON текстом, **молча конвертируется** —
узлы того же ответа разбираются, и источник становится обычным
управляемым приложением, без запроса и повторной загрузки. При этом
Qubiq делает одну попытку восстановления: повторяет тот же URL с
добавленным `/json` (с сохранением запроса и гарантированным User-Agent
`Happ/4.0`) — пригодный управляемый провайдером результат заменяет
обычный, а любая ошибка или не-провайдерский ответ оставляет исходный
обычный результат. Сохранённый URL никогда не переписывается.

## Поведение обновления {#refresh-behaviour}

- Потяните список вниз, чтобы обновить **все** источники за один проход.
- Автообновление работает от общего переключателя и интервала
  **24/72/168 часов** — либо от `profile-update-interval` провайдера для
  каждого источника.
- Обновление объединяет: одинаковые новые строки наследуют избранное,
  задержку, порядок и ваш выбор прежней строки; работающие конфигурации
  не переписываются на ходу.
- Неудачное обновление оставляет старый кэш, тариф и черновики —
  обновление никогда не может опустошить ваш список.

## Информация о тарифе {#plan-information}

Провайдеры, сообщающие `subscription-userinfo`, передают Qubiq байты
трафика (`upload`/`download`/`total`) и метку `expire`. Карточка группы
показывает использованное и срок — тонкая полоса «израсходовано/всего»
для лимитных тарифов, текст для безлимитных — с пометкой, что это данные
провайдера, а не живой трафик приложения, и с предупреждающим оттенком в
последние 7 дней. `expire=0` означает бессрочность. Истёкший или
исчерпанный тариф только информирует — подключению он не мешает. На
мобильных устройствах можно напомнить за 72 часа до истечения, если
провайдер включает эту опцию.

## Поля провайдера {#provider-fields}

Панели управляют частями интерфейса через заголовки ответа или комментарии
`#key: value` в теле. Для текстовых и URL-полей валидный заголовок
выигрывает у одноимённого ключа в теле, а отсутствующие или невалидные
значения заголовков могут дополняться из тела; флаги вроде напоминания
об истечении и блокировки сворачивания объединяются логическим ИЛИ. Поля,
которые понимает Qubiq:

Ведёте панель? Полный справочник — правила валидации, соответствие цветов
Happ, лимиты логотипа — в [«Провайдерам»](providers.md).

| Поле | Что вы видите |
| --- | --- |
| `profile-title` | Задаёт название источника, если вы не ввели своё |
| `subscription-name` | Запасной вариант названия после `profile-title` |
| `content-disposition` | Имя файла — последний запасной вариант названия |
| `profile-description` | Дополнительный текст под названием провайдера |
| `subscription-userinfo` | Трафик и срок тарифа на карточке группы |
| `announce` | Строка объявления на карточке группы |
| `announce-url` | Делает объявление нажимаемым (веб или Telegram) |
| `support-url` | Действие «Поддержка» (веб, Telegram или email) |
| `support-email` | Запасной email, когда `support-url` нет |
| `profile-web-page-url` | Действие «Сайт» на страницу провайдера |
| `homepage` | Запасной сайт, когда `profile-web-page-url` нет |
| `profile-update-interval` | Период обновления источника (1–720 ч) |
| `new-url` / `new-domain` | Адрес подписки переносится автоматически |
| `fallback-domain` | Зеркало, пробуемое один раз при сбое URL |
| `subscriptions-collapse` | `0`/`false` закрепляет группу открытой |
| `notification-subs-expire` | Включает напоминания об истечении (мобильные) |
| `color-profile` / `profile-logo` | Тема и логотип провайдера — см. [Оформление провайдера](subscriptions.md#provider-branding) |

Пустое редактируемое название разрешается как `profile-title` →
`subscription-name` → имя файла из `content-disposition` → хост URL;
введённое вами название всегда выигрывает и переживает обновления. Поля
провайдера отзываются, когда пропадают из следующего ответа, и
очищаются при изменении URL запроса.

## Оформление провайдера {#provider-branding}

Провайдер может перекрашивать приложение, пока его подписка используется —
это делают два поля ответа:

- **`color-profile`** — JSON-тема для палитры приложения. Темы,
  написанные для Happ, применяются без изменений; Qubiq также принимает
  свои семантические слоты палитры напрямую (канонический слот выигрывает
  у алиаса Happ для того же слота). Только hex-значения, лимит 16 КБ,
  неизвестные ключи пропускаются, некорректный документ игнорируется.
  Литерал `resetcolors` — как и удаление поля — отзывает тему.
- **`profile-logo`** — знак провайдера на панели приложения, карточке
  группы и странице деталей. Встроенные `data:`-изображения или
  HTTPS-URL (≤512 КБ, проверка формата, кэш между обновлениями; неудачная
  повторная загрузка оставляет кэш, отозванное объявление очищает его).

Оформление следует за используемой подпиской — подключённый профиль
провайдера, иначе выбранный источник или сервер, иначе единственный
оформленный провайдер. Смена источника меняет тему; удаление источника
возвращает обычную. Страница деталей каждой подписки перечисляет, что
задал провайдер, и несёт переключатель **«Оформление провайдера»**,
отключающий это для источника — выбор ваш и переживает правки и
обновления. Оформление никогда не трогает заголовок окна, имя приложения
и то, что вы можете редактировать.

## Отправить журналы {#send-logs}

Полоса карточки группы также несёт действие **«Отправить журналы»** — оно
пишет один пакет `qubiq-diagnostics-*.txt`; на мобильных устройствах он
отдаётся системному меню отправки, на компьютере — сразу диалогу
сохранения. Пакет содержит:

- метаданные приложения, платформы и подключения, живые счётчики трафика
  и результаты проверки маршрутов;
- поля панели источника, включая HWID — **никогда** его URL;
- живой повторный запрос URL подписки — статус и заголовки ответа
  записываются дословно;
- рабочую конфигурацию Xray с учётными данными, замаскированными как
  `***`, и пути файлов ядра, обрезанные до имён;
- последние 256 КБ каждого журнала ядра — журнал ошибок уровня warning
  всегда собирается за сеанс, поэтому он есть в пакете даже при
  выключенной записи журналов.

В отключённом состоянии или после неудачного запуска пакет всё равно
восстанавливает конфигурацию предыдущего сеанса (так же замаскированную)
и объявленные пути журналов. Пустые журналы помечаются `(empty)` —
ничего не опускается молча.

## Перенос адреса и зеркала {#address-migration-fallback}

Когда домен провайдера заблокирован или переехал, ответ старого URL может
нести `new-url` (заменяет весь URL подписки) или `new-domain`
(переписывает только хост HTTPS-URL). Объявленная цель принимается
**только после проверки** — Qubiq скачивает её через обычный конвейер и
сохраняет, только если она возвращает пригодную подписку. Проверка идёт
при добавлении и при каждом обновлении — по одному переходу за
обновление, каждый ответ планирует следующий своим объявлением.

Неудачная цель запоминается для источника и повторяется при каждом
обновлении — текущий URL тем временем продолжает работать, так что
провайдер может объявить новый адрес до его запуска. Новейшее объявление
заменяет запомненное; ожидающая цель сбрасывается, когда провайдер
перестаёт её объявлять или вы меняете запрос. Если текущий URL совсем
перестаёт отвечать, запомненная цель пробуется сразу как адрес
восстановления. Цель, конфликтующая с другой сохранённой подпиской,
откладывается без проверки и принимается автоматически, когда конфликт
разрешается.

`fallback-domain` — это зеркало, а не переезд. Успешный ответ может
объявить голый хост зеркала; когда сохранённый URL позже перестаёт
отвечать, тот же запрос повторяется один раз с подменой хоста на зеркало —
порт, путь и запрос сохраняются — и данные зеркала обслуживают это
обновление. Сохранённый URL никогда не переписывается на зеркало: каждое
обновление сначала пробует настоящий домен, ожидающая цель переноса
важнее зеркала, а ответ зеркала сам может объявлять переносы. Зеркало
остаётся взведённым, пока настоящий URL снова не ответит или пока вы не
измените запрос.

## Сохранённые поля запроса {#stored-request-fields}

Каждый источник также хранит собственные значения запроса — User-Agent,
пару ключей Age и идентичность HWID — из сохранённого или стандартного
состояния:

- **User-Agent** — по умолчанию совместимый UA для распознавания панелью.
- **Ключи Age** — где есть, `ageSecretKey` расшифровывает **локально**, а
  `agePublicKey` уходит на сервер через `X-Age-Public-Key`. Age защищает
  только тело ответа — он не скрывает URL и не заменяет HTTPS, а при
  неудачной расшифровке остаётся старый кэш.
- **HWID** — случайный UUID на источник, отправляемый как `x-hwid` с
  **каждой** загрузкой подписки; отключить нельзя, и
  `subscription-always-hwid-enable` не поддерживается. Это никогда не
  аппаратный, рекламный или системный идентификатор, он не появляется в
  ссылках и конфигурациях Xray, а кросс-доменные редиректы навсегда
  снимают его для этого запроса. Идентичность переживает правки URL —
  новая появляется только при удалении и пересоздании источника.

## Ссылки «Добавить в Qubiq» {#add-to-qubiq-links}

Провайдеры могут ставить на панель кнопку `qubiq://add?url=…&name=…` —
нажатие открывает заполненную форму подписки (название необязательно);
ничего не сохраняется и не подключается без вашего подтверждения.
`qubiq://import?data=…` делает то же для содержимого узла или
конфигурации, принимая текст в Base64, Base64url или percent-encoding.
Ссылки несут учётные данные в открытом виде — провайдерам стоит
обращаться с ними как с секретами и не вставлять настоящие токены в
примеры. Провайдеры могут сгенерировать кнопку с помощью
[конструктора ссылок](providers.md#link-builder).

## Действия источника {#source-actions}

Действия заголовка группы открывают страницы **изменения** источника
(название и URL), **отправки**, обновления и удаления. Правка URL очищает
метаданные провайдера до следующего обновления; удаление источника
очищает его кэши и связанные выборы.
