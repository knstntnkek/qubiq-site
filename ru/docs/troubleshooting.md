# Устранение неполадок и вопросы

## Первое: заметка об ошибке <!-- #first-stop-the-failure-note -->

Когда попытка подключения не удалась, кнопка показывает **«Повторить»** с
настоящей причиной рядом — читайте её первой; она сообщает реальную фазу
и ошибку, а не общее сообщение. Имена строк тоже отражают реальный сеанс:
имя подключённого сервера — фактический вход, который может отличаться от
закреплённого, если сработал запасной автовыбор.

При сообщении об ошибке через
[issues репозитория сайта](https://github.com/knstntnkek/qubiq-site/issues)
укажите платформу, версии приложения и ядра («Настройки → О приложении»)
и шаги воспроизведения. При проблемах с провайдером или подключением
действие **«Отправить журналы»** в группе делится пакетом
`qubiq-diagnostics-*.txt` с замаскированными учётными данными и без URL
подписки — он покрывает даже предыдущий сеанс после неудачного запуска и
повторно запрашивает этот URL вживую, чтобы дословно записать статус и
заголовки ответа. Приложите его к issue вместо того, чтобы вставлять сырые
конфигурации или журналы самостоятельно.

## Подключение не удаётся или виснет <!-- #connect-fails-or-hangs -->

- **Нечего запускать** — плану нужен хотя бы один активный читаемый
  кандидат: узел или полная конфигурация в режиме источника. Обновите
  подписку с пустым кэшем.
- **macOS System Extension ждёт** — разрешите её: macOS 15+ *«Основные →
  Объекты входа и расширения → Сетевые расширения»*; macOS 14- *«Конфиденциальность
  и безопасность»*. Подключение повторяет активацию при новой попытке.
- **Первое подключение Windows EXE** — одноразовое повышение UAC
  регистрирует задачи *Qubiq VPN Core*; отказ оставляет ядро без
  возможности запуска.
- **Исходящий интерфейс Windows/Linux** — отсутствующий или
  недействительный сохранённый интерфейс предложит выбрать заново при
  подключении.
- **Разрешение отклонено раньше** — отклонённые разрешения VPN/локальной
  сети не спрашиваются при каждом входе, но подключение повторяет
  авторизацию; нажмите пояснение, чтобы открыть системные настройки.

## Подключено, но трафик не идёт <!-- #connected-but-nothing-flows -->

- Проверьте, какой сервер называет кнопка, — запасной автовыбор мог
  запустить другую (или провайдерскую) конфигурацию, когда обычных
  кандидатов не хватило.
- Строка провайдера/Remnawave запускает **свою** маршрутизацию —
  настройки умной маршрутизации и режимов трафика к ней не применяются.
- Для сеансов приложения решает сохранённый набор умной маршрутизации —
  см. [«Маршрутизация»](routing.md).

## Задержка выглядит странно <!-- #latency-numbers-look-wrong -->

- Проверки идут **через VPN** при подключении — проверяйте без
  подключения для честных цифр.
- Строки провайдера (Remnawave) намеренно не показывают задержку — они
  не участвуют в проверках отдельных outbound.
- Состояния «не проверен»/«ошибка» показываются как статус, а не значение
  задержки — тайм-аут это не «9999 мс».

## Проблемы с подпиской <!-- #subscription-problems -->

- **Обновление не удалось** — старый кэш, тариф и ваши правки сохранены;
  ошибка сидит на источнике. Проверьте URL и потяните для обновления ещё
  раз.
- **Remnawave вернула ссылки, а не JSON** — узлы молча импортируются как
  обычная подписка приложения, затем одна попытка с `/json` возвращает
  вид провайдера, если он есть на панели.
- **Провайдер переименовал/перенёс подписку** — цели
  `new-url`/`new-domain` принимаются только после того, как отвечают
  пригодной подпиской; неудачная цель запоминается и повторяется при
  каждом обновлении, а ручная правка URL очищает метаданные провайдера до
  следующего обновления.
- **Основной URL лежит, у провайдера есть зеркало** — объявленный
  `fallback-domain` пробуется один раз за обновление с подменой хоста;
  сохранённый URL сам на него никогда не переписывается.
- **Полоса тарифа пропала** — провайдер перестал присылать
  `subscription-userinfo`; отозванные поля очищаются тем ответом, который
  их не прислал.

## Вопросы <!-- #faq -->

**Предоставляет ли Qubiq VPN-серверы?**
Нет — это клиент для серверов и подписок, которые приносите вы.

**Где мои данные?**
В локальной базе приложения — узлы, ключи, HWID, кэши тарифов. Ничего
никуда не синхронизируется, пока вы сами не привяжете хранилище копий.

**Что отправляет HWID?**
Случайный UUID, сгенерированный один раз при установке приложения, — не
аппаратный, рекламный или системный идентификатор. Он уходит вашим
провайдерам подписок с каждой загрузкой подписки; отключить нельзя.

**Где настройки маршрутизации, туннеля и серверов?**
В *«Настройки → Расширенные»*: **«Маршрутизация»**, **«Серверы»** и
**«VPN-туннель и Xray»**. Избранное, группы вручную и порядок живут в
менеджере серверов.

**iOS нельзя поставить из App Store?**
Пока `.ipa` требует sideload или корпоративную подпись.

**Есть ли телеметрия?**
Нет — ни аналитических SDK, ни отчётов о сбоях, ни аккаунтов. Журналы
локальны и включаются по желанию.
